*\*Note on 10k MRR: The 30 benchmark queries have relevance labels tied to the original 1,000 papers. In a 10,000 corpus, many newly indexed papers are also genuinely relevant to the query and rank at #1–#2, naturally lowering exact ground-truth rank matching while expanding coverage (R@10 remains high at ~82%).*

### Differences from the plan

These are all explained openly in the final report.

- **Benchmark labels.** The relevance labels were drafted with AI assistance. The 30 queries
  were written before either search system was run. **Đông must re-judge the labels** in
  `tests/judging_pool.json` (see `docs/benchmark_protocol.md`).
- **Precision@5 target.** The plan's "P@5 > 80%" cannot be reached. Most queries have only
  1–2 relevant papers, so no system can score above 0.367.
- **Statistical significance.** Semantic search wins 11 queries against BM25 and loses 3.
  With 30 queries this is not yet significant (sign test, p = 0.057).
- **Memory.** Memory use is 577 MB, not the estimated ~140 MB. PyTorch takes up most of it.
- **Dataset dates.** Every sampled paper was submitted in early January of its year. This is
  a side effect of how the arXiv API was queried. It is listed as a limitation.
- **Legal references.** The audit cites Vietnamese laws from 2025–2026. Some article-level
  details are marked unverified; Đông should confirm them.

### How a search works

1. `ingest.py` downloads papers from arXiv into `data/raw/arxiv_sample_10000.json` (or `_1000.json`).
2. `indexer.py` encodes `"title. abstract"` with `all-MiniLM-L6-v2`. Precomputed embeddings are cached in `.npz` format. On index builds, if the `.npz` file exists, vectors are loaded directly into ChromaDB in seconds without loading PyTorch or running model inference.
3. In-memory `AuthorIndex` maps lowercased diacritic-stripped author tokens to paper IDs, allowing instant accent-insensitive author filtering without full collection scans.
4. `app.py` allows selecting between three search modes:
   - **Hybrid (Dense + BM25)**: Combines neural vector search and BM25 rank lists via Reciprocal Rank Fusion (RRF, $k=60$).
   - **Semantic vector only**: Standard dense cosine similarity retrieval via ChromaDB.
   - **Keyword only (BM25)**: Lexical exact-term matching via Rank-BM25.
5. Each paper is displayed with its similarity match score, metadata, key terms, BibTeX/APA/IEEE export, and "Find similar" button.

## 3. How to run

### 3.1 One-time setup (already done on this machine)

```bash
python -m venv .venv
.venv/Scripts/pip install torch==2.14.1 --index-url https://download.pytorch.org/whl/cpu
.venv/Scripts/pip install -r requirements.txt
.venv/Scripts/python -m src.indexer        # build the index (~1 min)
```

### 3.2 Environment variables (needed in every new terminal on this machine)

The C: drive is almost full, so temporary files and model caches must go on G:.

Git Bash:
```bash
cd /g/hcmut-ailib
export TMP=G:/hcmut-ailib/.cache/tmp TEMP=G:/hcmut-ailib/.cache/tmp HF_HOME=G:/hcmut-ailib/.cache/huggingface HF_HUB_OFFLINE=1 PYTHONIOENCODING=utf8
```

PowerShell:
```powershell
cd G:\hcmut-ailib
$env:TMP="G:\hcmut-ailib\.cache\tmp"; $env:TEMP=$env:TMP; $env:HF_HOME="G:\hcmut-ailib\.cache\huggingface"; $env:HF_HUB_OFFLINE="1"; $env:PYTHONIOENCODING="utf8"
```

### 3.3 Run the web app

```bash
.venv/Scripts/streamlit run src/app.py
```

Open **http://localhost:8501**. The first load takes about 15 s; after that each search is
nearly instant. Press **Ctrl+C** to stop.

Things to try:
- Search for `mixing two languages within one conversation`. The top result should be
  *A Survey of Code-switching*.
- Use the sidebar filters: Top-K, year range, category, author.
- On a result card, open "Cite this paper" and copy the BibTeX.
- Click "Find similar", then open the "Similar papers" tab.

### 3.4 Run the tests

Stop the web app first. This machine has little free RAM.

```bash
.venv/Scripts/python -m pytest -q                         # all 33 tests, ~26 s
.venv/Scripts/python -m pytest -q -s tests/test_retrieval.py   # also prints MRR / P@5
```

### 3.5 Other commands

| Command | What it does |
|---|---|
| `.venv/Scripts/python -m src.evaluate` | Full benchmark on 30 queries (MRR, P@5, latency, memory, PCA); writes `reports/results/` |
| `.venv/Scripts/python -m src.evaluate --scifact` | Benchmark on international standard BEIR-SciFact dataset (5,183 docs, 300 test queries) comparing Semantic, Hybrid RRF, and BM25 |
| `.venv/Scripts/python -m src.evaluate --pool` | Regenerates the judging pool |
| `.venv/Scripts/python -m src.indexer` | Builds ChromaDB index (loads precomputed `.npz` if present, ~90 s for 10k, ~4 s for 1k) |
| `.venv/Scripts/python -m src.indexer --dataset data/raw/arxiv_sample_1000.json` | Indexes specific dataset file |
| `.venv/Scripts/python -m src.ingest --target 10000` | Ingests 10,000 papers with automatic pre-seeding and checkpointing |
| `.venv/Scripts/python -m src.ingest --target 1000` | Ingests 1,000 papers baseline |
| `.venv/Scripts/python reports/build_reports.py` | Rebuilds all PDF reports |
| `.venv/Scripts/python docs/draw_architecture.py` | Redraws the architecture diagram |
| `.venv/Scripts/python docs/take_screenshots.py http://localhost:8501` | Takes new screenshots (the app must be running) |

### 3.6 Troubleshooting

| Problem | Fix |
|---|---|
| "Could not open the vector index" | Run `.venv/Scripts/python -m src.indexer` |
| `No space left on device` | Set the environment variables in 3.2 |
| `not enough memory` during tests | Stop the Streamlit app and close other heavy programs |
| Port 8501 already in use | Add `--server.port 8502` to the run command |
